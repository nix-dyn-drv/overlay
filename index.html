The headline number

nixgg's mechanism rebuilds only 2 of openssl's 2213 translation units on a one-line patch, and its batchGroups feature collapses lua's ~30 per-TU compiles into 1 archive derivation for a 1.71x build-phase win. dyn-drvs' mechanism builds clean on freetype, giflib, tree, figlet, and nnn, but freetype's cold build is ~6.7x slower than a plain rebuild (measured directly in this repo). Per-TU acceleration only pays off when each compile unit costs more than the ~80ms registration overhead it adds. A wider survey found every dyn-drvs failure traces back to either autotools' dependency-tracking idiom or cmake's generated build systems — every clean pass used a plain, hand-written Makefile.

Bugs found in dyn-drvs

Building and surveying real nixpkgs packages against this repo surfaced 16 distinct bugs in accelerate.mkAcceleratedStdenv, 12 fixed upstream so far, each written up for the dyn-drvs maintainer:

  • discoverTree's dependency scan can't see a link step's own inputs when the link is driven through cc/c++ directly (cmake, libtool) — confirmed on zstd, pcre2, mpfr; not universal (tinycbor's own cc-driven links build fine).
  • autoreconfHook's dynamically-injected build phase gets silently dropped by a static phase list.
  • CMake's compiler-flag probes aren't recognized as passthrough-eligible, so a deferred stub falsely reports success.
  • The finalAttrs.finalPackage self-reference nixpkgs injects for ordinary packages is missing from the accelerated stdenv's own mkDerivation.
  • cmake builds can fail per-TU compiles with a source-not-found error — confirmed on xxHash, re2 (fixed), and tinycbor's real (cmake-based) recipe.
  • A freshly-linked binary can lose its execute bit, breaking any Makefile that runs its own just-built binary as a self-test (libb64) — a permanent architectural limitation, not fixable within dyn-drvs' single-buildPhase design. nixgg's two-phase pattern sidesteps the same wall on the same package.
  • phases.split forces single-output but doesn't clear an inherited outputBin/outputMan literal override (libpng, libtasn1) — fixed.
  • Secondary compiler side-outputs (automake's -MF depfiles) don't survive the sandbox boundary, breaking the classic autotools depcomp idiom (gperf) — fixed.
  • A bare -l<name> link argument (a linker search-path reference, not a literal path) is never resolved back to its producing derivation (x265's 10/12-bit HDR variants).
  • A libtool-generated unversioned .so symlink is never registered as an alias for the real, versioned file dyn-drvs actually tracks — the next link step referencing it fails (libpng, libtasn1).
  • postInstall can run before the placeholder-rooted build tree gets restored into the real $out, so it reads a directory that doesn't exist yet (mosh).
